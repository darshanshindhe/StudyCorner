### Problems faced and fixes
- **Problem:** `pip install pymupdf` failed with a long build error (cmake, ninja, swig).
- **Cause:** My venv was using Python 3.14, which is too new. Libraries like PyMuPDF had no prebuilt installer (wheel) for it, so pip tried to build from source, which needs C++ build tools.
- **Fix:** Installed Python 3.12, deleted the old venv, created a new one with `py -3.12 -m venv venv`, then reinstalled.
- **Lesson:** ML libraries lag behind the newest Python version. Always check `python --version` before creating a venv.
- **Problem:** `FutureWarning: fitz API is deprecated`.
- **Fix:** Changed `import fitz` to `import pymupdf as fitz`.

### Observations and limitations (important for README and interviews)
1. **Text inside images is not read.** In the finance notes, the NPV and IRR formulas and some tables are images, so only the surrounding text is extracted. A question like "what is the NPV formula?" can only be answered from the words around it. Possible fix: OCR or a vision LLM (Level 2 or 3 upgrade).
2. **Tables extract as broken lines.** Comparison tables lose their row/column structure. This may confuse the LLM. Need to test later.
3. **Lecture slides have a two-column problem.** In the microprocessor slides, two columns (data addressing vs memory addressing) get mixed line by line. Paragraph-style notes work better than slides for chunking.
4. **Page breaks merge sections.** Text like "inefficiencies.(c) Large Amount of Funds" shows that a section spanning two pages gets split, and headers or footers mix into the text.
5. **No fully scanned pages were detected** by the Level 1 check, so OCR is a nice-to-have, not a must-have.
